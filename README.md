# A系/B系 分離型Web・APクラスタ 負荷分散＆リリースシミュレーター

新任・若手エンジニア向けに、A系・B系でトラフィックが分離されたマルチティア環境において、**「実務運用ジョブ（waitあり/waitなし切離・組込）」**、**「JSESSIONIDによるスティッキーセッションテーブル管理」**、**「各サーバ（Web/AP/DB）での処理滞留時間」**、**「HTTPリクエスト往復フロー（行き: 青 / 帰り: 緑）」**、**「SORRYサーバ連動」**の挙動を視覚的かつインタラクティブに理解できるWebベースのシミュレーションツールです。

---

## 🛠️ 主な機能と実務仕様

### 1. 実務運用ジョブ（9種類のプリセット）
デフォルト状態は「通常稼働」。右側パネルから以下のジョブをワンクリックで投入可能です：

| ジョブ名 | 挙動・処理内容 |
| :--- | :--- |
| **`WEB-A系切離-waitあり`** | Web A系（02, 04）を `up/under-maintenance(manual)` に遷移。**新規通信は即時拒否しつつ、30秒間既存通信（セッション確立済みクライアント）の処理をそのまま維持（Graceful Drain）**。30秒経過（wait満了）後に次回リクエストからもう片系（B系）へ新規振り分け。 |
| **`WEB-A系切離-waitなし`** | Web A系（02, 04）を `up/under-maintenance(manual)` に遷移。**次回以降の新規リクエスト転送を即時停止**（B系へ切り替え）。**すでにExternal LBを通過してWeb/AP/DBでインフライト処理中の通信は、レスポンスまで正常に保証**されます。 |
| **`WEB-A系組込`** | Web A系（02, 04）を `up/active` に復帰。External LBの均等負荷分散を再開。 |
| **`WEB-B系切離-waitあり`** | Web B系（01, 03）の30秒ドレイン切離。wait中は既存セッションを維持、満了後に次回からA系へ切替。 |
| **`WEB-B系切離-waitなし`** | Web B系（01, 03）の即時切離。次回以降の新規転送を即時停止し、通過済みインフライト通信は正常レスポンスを保証。 |
| **`WEB-B系組込`** | Web B系（01, 03）の `up/active` 復帰。 |
| **`WEB全台切離-waitあり`** | Web全4台の30秒ドレイン切離。30秒後に受け手全滅により **SORRYサーバ（up/active）** が発動。 |
| **`WEB全台切離-waitなし`** | Web全4台の即時強制切断切離。即座に **SORRYサーバ（up/active）** が緊急発動。 |
| **`WEB全台組込`** | Web全4台を `up/active` に復帰。SORRYサーバは自動で `up/standby` に戻る。 |

### 2. クライアント数（1〜10台）と APサーバによる JSESSIONID 採番管理
- **クライアント数スライダー（1〜10台）と美しい垂直センタリング配置**:
  - `1. Clients` 列は画面の垂直中央（External LBと高さが揃う位置）に美しくセンタリング配置されます。
  - スライダーを動かすと、リアルタイムにクライアント数（1〜10台）が増減します（1〜4台でも上部に寄らず中央にバランス良く整列）。
  - 各クライアントカードの位置から独立して青色パケットがExternal LBへ発射され、戻りパケットがそれぞれのクライアントへ帰還します。
- **クライアント追加時のセッション未所持 ＆ 初回アクセスでのAP採番ライフサイクル**:
  - スライダーでクライアント数を増やした際、**新しく追加されたクライアント（Client-05〜10等）は最初からセッションを持たず、`(新規接続)` 状態でクリーンに追加**されます。
  - そのクライアントから最初のリクエストが送出され、健全なWeb/APを経てレスポンス（緑色 200 OK）が帰還した瞬間に、**到達したAPサーバによって新しい `JSESSIONID` が1回だけ採番**され、セッションテーブルに登録されます。
- **クライアント減少時（切断）の即時パケット破棄 ＆ 再接続時のクリーン初期化**:
  - スライダーでクライアント数を減らした際、実務のTCPコネクション切断（Host Unreachable / RST）と同様に、**離脱したクライアントに関するインフライトパケット（往路・復路問わず）を即座に破棄（消滅）**させます（消えたクライアント宛てのパケットが画面外へ迷走することを完全防止）。
  - 同時にセッションテーブルおよびコネクション情報も破棄されるため、直後にクライアント数を増やして再起動した場合でも**昔の通信レスポンスを受け取ることはなく、完全な新規接続（`(新規接続)`）として新たにリクエストを開始**します。
- **1クライアントあたりReq流量スライダー**:
  - 1台あたり送出するHTTPリクエストレート（`0 〜 30 req/s`）を調整可能。
  - 全体流量（Req/s）＝ クライアント数 × 1台あたりReq に自動連動します。
- **JSESSIONIDはAPサーバにて採番管理 ＆ 同一クライアントで継続利用（Sticky）**:
  - `JSESSIONID` は**初回通信時に到達したAPサーバ（Tomcat等）により採番**されます（例: `JSES-A-AP02-4741` のように担当AP名を含む識別子）。
  - クライアントカードおよびセッション管理テーブルに、採番された `JSESSIONID` と担当AP（`AP (Sticky)`）が表示されます。
  - **WEB-AP（Internal LB）間の通信は、そのJSESSIONIDを採番したAPサーバへ確実に固定ルーティング**されます。
  - **エラー（赤色パケット）を受け取るまでは、1クライアントで同一のJSESSIONIDを維持**し続けます（リクエストの都度更新されることはありません）。
- **AP障害・片系切り離し時のエラー受領 ＆ 新APでの再採番ライフサイクル**:
  - 担当APサーバが停止（`down/-`）した場合、Internal LB（VIP）から **503 エラー（赤色パケット）** が返却されます。
  - **エラー（503/504赤パケット）を受領した時のみ、既存の `JSESSIONID` は破棄**され、クライアントカードは `(再発行待ち)` 表示になります。
  - 次回リクエストはセッション未所持として健全なAPへルーティングされ、**正常戻り（200 OK緑パケット）時に新APにて新しいJSESSIONIDが1回だけ採番**されます。
  - 採番後は再びエラーを受け取るまで、その新JSESSIONIDを継続利用します。

### 3. WEB-AP間（Internal LB）の固定ルーティング仕様とセッション管理
- **WEBサーバ単位のAP固定（送信元Webパーシステンス）**:
  - WEB-AP間の内部負荷分散（Internal LB）は、**WEBサーバ単位でAPサーバへ固定ルーティング**されます（例: Web-02 ➜ AP-02、Web-04 ➜ AP-04）。
- **割り振りアルゴリズム（コネクション最少 ＆ 若い号機順）**:
  - WebサーバがInternal LBへリクエストを送信する際、まだAPに固定されていない（初回、または30秒無通信リセット後）場合は、該当系（A系: AP-02, 04 / B系: AP-01, 03）の稼働中APの中から**「現在のコネクション数が最も少ないAPサーバ（Least Connection）」**に割り振られます。
  - 割り振られる前などコネクション数が同数の場合は、**「号機が若い順（例: AP-02 < AP-04、AP-01 < AP-03）」**を優先して割り振られます。
- **30秒無通信タイマーによる自動リセット（アイドルタイムアウト）**:
  - 各WebサーバからInternal LB経由でAP宛ての通信が**30秒間途絶えると、WEB-AP固定マッピングが自動的に解除（リセット）**されます。
  - 次回リクエスト発生時に、改めてコネクション最少（同数は若い号機順）ルールでAPが再選定・固定化されます。
- **AP障害時の即時フェイルオーバー**:
  - 固定先APが障害等で停止（`down/-`）した場合、30秒を待たずに固定は即時リセットされ、健全なAPへ自動フェイルオーバーされます。
- **セッション＆固定管理パネル**:
  - 右パネルの「セッション」タブにて、**各WEBサーバの固定先AP・無通信残り秒数（30sカウントダウン）・Conn数**、および**クライアントのJSESSIONID採番情報**がリアルタイムに確認できます。

### 4. サーバ処理滞留時間（スライダー調整）
サブバーのスライダーで各サーバでの処理時間（滞留秒数）をリアルタイムに調整できます：
- **WEB滞留時間**: `0.0s 〜 4.0s`（デフォルト: `0.5s`）
- **AP滞留時間**: `0.0s 〜 4.0s`（デフォルト: `1.0s`）
- **DB滞留時間**: `0.0s 〜 4.0s`（デフォルト: `0.8s`）

※パケットが各サーバに到達すると指定秒数カード内で滞留し、実務で時間のかかる処理（Tomcat Java処理やSQLクエリ実行）を視覚的に観察できます。

### 4. HTTPリクエスト往復フローと色ルール
- **行き（Request）**: **青色**（Client ➜ External LB ➜ Web ➜ VIP ➜ AP ➜ DB、またはSORRY宛て）
- **帰り（Response / 正常系 200 OK）**: **緑色**（DB ➜ AP ➜ VIP ➜ Web ➜ External LB ➜ Client）
- **帰り（エラー返却 503 Service Unavailable）**: **赤色**
  - **AP全台停止時の挙動**: リクエストは途絶えることなく**青色（行き）**でWebを経由してInternal LB（VIP-A / VIP-B）まで到達します。Internal LBは配下APが0台のため即座に**HTTP 503エラー（赤色）**を生成し、Web ➜ Ext LB ➜ Clientへ折り返し返却します。
- **SORRYサーバ**:
  - SORRYサーバ宛ての通信も共通ルール（**行きは青色** ➜ SORRY滞留 ➜ **帰りは緑色**）に従い、統一された視覚体験を提供します。

### 5. 負荷分散装置の死活監視とSORRYサーバ自動昇格
- **各サーバのステータス遷移**:
  - `up/active`：通常稼働状態（LBが均等にリクエストを分散）
  - `up/under-maintenance(manual)`：保守切り離し状態（死活監視ヘルスチェックは通っているが、運用ジョブにより新規受付を停止）
  - `down/-(ハイフン)`：死活監視障害（ヘルスチェック応答途絶を検知し、LBが即時切り離し実施）
  - `up/standby`：SORRYサーバ通常待機状態
- **SORRYサーバ連動**:
  - **WEB 4台が死んだ（down/-）になったときにのみ `up/active` に昇格**し、503 Sorry Page を返却。
  - WEBが1台でも復旧すると、自動的に `up/standby`（待機状態）へ復帰。
- **カオステスト操作**:
  - トポロジー上の各ノードカードをクリックすると、個別に死活監視障害（`down/-`）と復旧（`up/active`）をトグルできます。
  - 右パネルの「死活監視 障害テスト」セクションで、`[WEB全台 down/- (SORRY発動)]`、`[WEB全台 復旧]`、`[AP全台 障害発生]` をワンクリックで実行可能です。

## ⚙️ 外部定義ファイル (`config.js`) による構成カスタマイズ

本シミュレータは、HTMLコード（`index.html`）を直接変更することなく、同一ディレクトリの外部定義ファイル **`config.js`** を編集することでシステム構成や名称を自由に変更できます。

### カスタマイズ可能な項目
1. **負荷分散NW装置 (`networkDevices`)**:
   - `externalLb`: External LB の表示名、各系のラベル名
   - `internalLb`: VIP-A / VIP-B の代表IP、名称、ルーティング説明
   - `database`: Database の表示名、サブタイトル
2. **サーバ定義 (`servers`)**:
   - `web`: Webサーバ群（`Web-01`〜`04`、`SORRY`）の名称、IPアドレス、所属系（A/B/SORRY）、初期状態
   - `ap`: APサーバ群（`AP-01`〜`04`）の名称、IPアドレス、所属系（A/B）、バージョン、初期状態
3. **実務運用ジョブ定義 (`jobs`)**:
   - 実務運用ジョブの名称（例: `WEB-A系切離-waitあり`）、グループ（A系/B系/全台）、待機時間（`waitDuration: 30`）、バッジ文言、ボタンスタイル

設定ファイルを編集後、ブラウザをリロードするだけで画面全体のトポロジー表示・ジョブボタン・パケットルーティングに自動反映されます。

## 🚀 起動方法

### 方法1: ブラウザで直接開く
単一の自己完結型 HTML ファイル（`index.html`）のため、ファイルをダブルクリックするか、ブラウザにドラッグ＆ドロップするだけで即座に動作します（外部通信0件・完全オフライン対応）。

### 方法2: ローカルHTTPサーバーで起動
```bash
cd 負荷分散シミュレータ
python -m http.server 8088

# ブラウザでアクセス:
# http://127.0.0.1:8088/index.html
```
